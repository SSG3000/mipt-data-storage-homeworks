# mipt-data-storage-homeworks

## HW_DB_1. Повторение развертывания базы и работы с ней

Для целей повторения развертывания базы и работы с ней привожу свои шаги.

### Шаг 1. Подготовил окружение

Установил Docker, Docker Compose и DBeaver, затем открыл корневую папку репозитория.

Перед первым запуском я создал внешний Docker-том для данных PostgreSQL:

```bash
docker volume create mfti-postgres-data
```

### Шаг 2. Запустил PostgreSQL

Из корневой папки репозитория я запустил контейнер:

```bash
docker compose up -d
```

После запуска я проверил, что контейнер `mfti-postgres` работает:

```bash
docker ps
```

### Шаг 3. Подключился к PostgreSQL через DBeaver

Я создал подключение со следующими параметрами:

- хост: `localhost`;
- порт: `5432`;
- пользователь: `postgres`;
- пароль: `postgres`;
- начальная база: `mfti_store`.

### Шаг 4. Создал учебную базу

В подключении к базе `mfti_store` я выполнил скрипт
`HW_DB_1/sql/00_create_database.sql`.

Скрипт создает базу `hw_db_1`. После его выполнения я обновил список баз в DBeaver и переключил подключение на `hw_db_1`.

Если база `hw_db_1` уже существует, повторно выполнять создание не нужно. Для полного развертывания с нуля сначала необходимо убедиться, что в ней нет нужных данных, и только после этого удалить старую учебную базу.

### Шаг 5. Создал исходный слой raw

В базе `hw_db_1` я выполнил скрипт
`HW_DB_1/sql/01_create_raw_tables.sql`.

Он создает схему `raw` и четыре исходные таблицы, в которых данные первоначально хранятся в текстовом виде:

- `raw.customers`;
- `raw.products`;
- `raw.orders`;
- `raw.order_items`.

### Шаг 6. Загрузил CSV-файлы

Выполнил скрипт `HW_DB_1/sql/02_load_raw_data.sql`.

CSV-файлы загружаются из каталога `/workspace/HW_DB_1/data/raw/`. Этот путь доступен внутри контейнера, поскольку корневая папка репозитория подключена в `compose.yaml` как `/workspace`.

После загрузки я проверил контрольное количество строк:

- `customers` — 5 000;
- `products` — 300;
- `orders` — 25 000;
- `order_items` — 50 000.

### Шаг 7. Создал нормализованный слой core

Выполнил скрипт `HW_DB_1/sql/03_create_core_tables.sql`.

Он пересоздает схему `core`, создает типизированные таблицы, первичные и внешние ключи, ограничения и индексы. Географические атрибуты клиентов вынесены в отдельную таблицу `core.locations`. !!! ВСПОМОГАТЕЛЬНАЯ ТАБЛИЦА

### Шаг 8. Преобразовал и перенес данные

Выполнил скрипт `HW_DB_1/sql/04_transform_to_core.sql`.

На этом этапе я преобразовал текстовые значения в нужные типы, исключил повторы по бизнес-ключам и загрузил данные из `raw` в `core`.

После преобразования я получил:

- `locations` — 2 899 строк;
- `customers` — 5 000;
- `products` — 300;
- `orders` — 25 000;
- `order_items` — 50 000.

### Шаг 9. Проверил качество данных

Выполнил скрипт `HW_DB_1/sql/05_data_quality_checks.sql`.

С его помощью я проверил:

- наличие первичных и внешних ключей;
- количество исходных и уникальных строк;
- отсутствие дублей по бизнес-ключам;
- соответствие количества строк до и после преобразования;
- отсутствие нарушений ссылочной целостности.

В загруженных данных дубли по бизнес-ключам и потерянные внешние связи не обнаружены.

### Шаг 10. Выполнил аналитические запросы

Выполнил скрипт `HW_DB_1/sql/06_analytical_queries.sql`, содержащий все 11 запросов из задания.

Дополнительный запрос 11.1 выводит первые и последние 10 строк результата запроса 11. Он используется только для компактного представления результата на скриншоте для запроса 11.

Я проверил результаты запросов в DBeaver и сохранил скриншоты в каталоге `HW_DB_1/report/screenshots/`. В итоговый отчет я включаю ER-диаграмму, описание нормализации, результаты проверки качества данных, тексты запросов, скриншоты и личную рефлексию.
